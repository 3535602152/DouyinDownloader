# 空页与游标推进：匿名化分页案例

本记录保留历史问题的技术结论，源、游标和计数均为说明性示例，不包含实际账号、
关注关系或本地数据库记录。当前行为以代码和回归测试为准。

接口可以返回 `status_code=0`、`aweme_list=[]`、`has_more=1`，同时提供向前推进的
`max_cursor`。这表示当前时间窗没有作品，应继续翻页，不能仅因列表为空归类为风控。
例如作者 A 的游标从 `3000` 走到 `2000` 时没有作品，下一页仍有作品。

旧逻辑在 `not items and has_more` 时抛错，且没有持久化新游标。未完成的全量扫描
重启后不断读取同一空页；每次尝试刷新检查时间，使增量扫描难以获得执行机会。

需要验证的边界：

- 合法空页继续翻页，并保存新的恢复游标。
- 游标重复、倒退或长期不推进由游标保护限制，不能无限循环。
- 失败重试保留进度，增量检查仍按调度策略运行。
- HTTP 200 空响应体、挑战页、403 和合法空 JSON 列表分别处理。
- 前台取消、后台让路和程序重启后，扫描状态保持一致。

相关实现位于分页解析、统一扫描服务及对应测试。原始抓取响应、账号资料和本地
排查记录不随源码发布。
