# Changelog

Notable user-facing and repository-level changes are recorded here.

## Unreleased

## 0.4.0 — 2026-10-24

- Prepared a new private release baseline, locked Python/Node dependencies, automated regression checks and Windows packaging. Login/cache files are excluded and release sources are scanned.
- Replaced the imageio FFmpeg binary with a source-built LGPL media component; third-party licenses and corresponding sources accompany the release.
- Source support is Python 3.12–3.14; Windows x64 builds use Python 3.12.

- The work player's up / down arrows are greyed out at the first and last work instead of silently doing nothing, and a work that the current search or filters leave out now steps through the full list instead of jumping back to the first work.
- The work player's comment panel shows a hidden work's saved comments (marked 作品已隐藏) instead of nothing, with the stickers and pictures the comment sync downloaded rather than their signed links, which expire after a few days; a failed online read only says 获取失败 with 重试. A new 作者 tab next to 评论 lists the comments the author wrote or replied under, each with only the author's replies: read online by walking every comment and reply page (Douyin has no author filter), and from the saved comments only for a hidden work. A sticker whose links all fail is hidden instead of showing a broken image.
- Comment sync reads a finished work's comments in full again sooner: at most daily (was every 3 days) once its comment count grew by 5 or more (was a tenth, at least 20). Page pacing and the risk pause are unchanged.
- Pictures in the work player's comments now open in an in-app image preview above the player, with a dark backdrop, a close button and Escape to dismiss. Original image URLs fall back through their mirrors, and closing restores the comment's focus and scroll position without opening a browser or downloading a file.
- The footer download panel has three tabs: 下载 (only the followed creators' works), 用户 (like/collect works, one row per subscription with its remaining count; a click shows its running and next queued work, 全部展开 lists up to 30 like the 下载 tab) and 评论. When a creator work becomes due while every download slot runs a like/collect work, one of those is put back in the queue (at most every 30 s) so the creator work starts at once.
- Creator full scans no longer stop at 200 waiting downloads (等待下载追上); they keep their page pace whatever the backlog. Automatic creator full scans now rank before like/collect downloads and subscription scans in the request scheduler, so the followed creators (checks, downloads, full scans) always go first. The 删除主播 dialog lists the creators being removed (scrollable, with local work count and size), and its checkbox lines up with its label. Settings: only the settings list scrolls, the category list follows the scroll position and jumps to a section instead of filtering (全部设置 removed).
- Several Douyin accounts can be logged in at once (设置 → 账号: 扫码添加, 设为主账号, 重新登录, 移除), kept in `.accounts.json`; `.cookies.json` still holds the main account's login and an existing login becomes the first account. The client keeps one session (cookie jar, msToken) per account and a task picks its account once (`use_account`); everything that does not name an account — creator checks, downloads, comment sync, the follow feed, the browser fallback — uses the main account. 导入关注主播 has an account picker. Each 喜欢 / 收藏 subscription is scanned with its own account's login when that account is in the library (no more 非当前账号); anyone else's public likes are read with the main account and nothing is deleted for them. Accounts take turns, one scan at a time. An expired login of another account only pauses that account's subscriptions; only the main account's pauses the background.
- Subscription scans page at the creators' pace (3–7 s, slower with a long download backlog) instead of 20–30 s, and every automatic one gives way to creator scans: it does not start while a creator check, feed read or full scan is queued or running, and stops between pages when one comes up (a full scan resumes from its saved page). Routine creator checks run every 30 minutes instead of 10; the follow feed every 16–24 minutes.

- In-app QR login now requests the code directly from Douyin's current passport API and displays it before starting the hidden browser. The same QR response and scoped guest cookies are handed to the official SDK for protected scan polling and confirmation; the browser must not generate a different initial code. A failed direct request falls back to the browser within a short timeout. Loading text updates preserve the spinner and QR image nodes. Fixed the bridge's `window` argument shadowing JavaScript's global window, which previously prevented QR login from starting.

- An endpoint waiting out a risk cooldown (e.g. comment replies answering empty, up to 60 s each time) no longer holds every other request back for that long; it had kept 导入关注主播 at "已获取 0 人" for minutes while the comment sync kept hitting the reply endpoint.
- 导入关注主播 no longer hangs at "正在读取关注列表… 已获取 0 人": the read had to wait behind a running batch of creator checks (same task lane) and now has its own lane; 取消 always closes the dialog, also while the read is still queued.
- Gallery pictures are saved full size again. Since 2026-09-30 Douyin has served the clean pictures scaled down (`tplv-dy-aweme-images-v2`, e.g. 1440x1920 for a 2160x2880 upload) to some `ttwid` device-id buckets, full size only watermarked; the saved login's `ttwid` was in that bucket, while a fresh one (or none) gets the full-size clean `tplv-dy-aweme-images` copies, in the API and the page alike. When a gallery comes back scaled, the client registers a new `ttwid` (at most every 6 hours per account), the work's detail is read again, and the new id is saved with the account's login.
- Gallery pictures were still saved with the "抖音号" watermark: aiohttp's yarl decoded `%2F` in the query, so every clean picture URL whose `x-signature` holds one answered 403 and the download fell back to the watermarked copy (also any signed CDN URL). Media and fallback API requests now send the URL exactly as given. Once, at start-up, galleries whose saved JSON shows such a picture (written in the same attempt as the JSON) are queued as a `watermark_fix` extra: all pictures are fetched again, one work every 60 s after a 10-minute delay, a copy with another extension is replaced, and live-photo motion pictures are rebuilt. Since 2026-09-30 Douyin's clean picture URLs are scaled down (e.g. 1440x1920 for a 2160x2880 upload) and full size comes only watermarked; a gallery's first picture is now taken from the cover's untouched `~noop` original, which is full size and clean.
- Downloads no longer pick Douyin's "抖音号" watermarked copies. Since the 2026-09-27 monitor asset rework (carried into the backend rewrite) the CDN fetcher re-ordered every candidate list by mirror speed alone, so a watermarked gallery picture or gallery cover (`download_url_list`, `tplv-dy-water`) or video on a faster host was downloaded instead of the clean one listed first; clean URLs now always come first and speed only orders within each group. Pictures shown online use the same watermark-free choice.
- Creator homepages keep the last online profile (counts, 抖音号, IP / region / age tags, signature, avatar and cover) in a `creator_profiles` table, with the avatar and cover saved under the data folder's `cache/creators/`. A homepage shows it at once and offline; each online visit replaces whatever changed and re-downloads a picture only when it is a different one.
- The work player slides to the next / previous work and gallery pictures slide sideways, instead of jumping.
- The work player has a comment panel (the comment icon or X), read live from Douyin like the web player: 10 comments per page as the list scrolls, replies folded under 展开N条回复 (3 first, then 10 at a time, then 收起), author tag and 作者赞过. It sits beside the picture, opens without an animation, stays open while works change, and saves nothing; hidden works say so instead of reading. The panel slides in while the picture gives way; emoji codes such as `[流泪]` are drawn with Douyin's emoji pictures (the table is cached for a week); a comment picture falls back through its mirrors and hides when none loads.
- Comment replies are requested with the web player's `item_type=0`; without it the endpoint answered with an empty body, which counted as risk control and paused every comment feature for hours. In the player an empty page is asked once more and never pauses anything. Reply pages are also requested from the video page (Referer) and, when the direct answer is empty, through the logged-in page. The player's rail uses the web player's own like / comment / collect / share icons, the 看相关 button is gone (its slot stays empty), and a work sliding away no longer covers the comment panel. Hovering like / comment / collect / share makes the icon hop; like turns red and collect yellow with a pop (shown locally only). The whole app now uses the Douyin web pages' font stack ("PingFang SC" → Microsoft YaHei on Windows).
- The background comment sync no longer pauses itself on empty reply pages. Every risk pause since it shipped (up to 24 h at level 7, without one work ever saved) came from `/comment/list/reply/` answering an empty body; the comment list itself never failed. A reply page that comes back empty is now asked once more through the logged-in page, and if still empty the comment is kept without those replies; only the comment list's own risk answers pause the sync.
- Comment sync saves every comment, in two passes at the same pace (3–7 s a page, no hourly cap). The first pass (the first 50 comments and 3 replies of each) runs for every work first, and a newly downloaded work goes ahead of the second; the second reads all remaining comments and every reply, the works with the fewest comments first, a page at a time, resuming where it stopped (restarts and risk pauses included) and giving way as soon as a work needs its first pass. Passes are merged into the database and `*_comments.json` (in Douyin's order, replies under their comment); a page that keeps failing three times ends that work with what was read. A finished work is read in full again when its comment count grew by a tenth (at least 20), at most every 3 days. The download panel's 评论 tab lists both queues, the second pass's progress measured against the work's whole comment count.
- Rebuilt creator-monitor downloads around whole works, one at a time: each attempt fetches a fresh detail (API, then the logged-in browser page), downloads media through a new segmented, mirror-ranking CDN fetcher, and completes once media + JSON are saved. Cover and gallery music are best-effort extras retried in the background; videos no longer fetch separate music and avatars are saved once per creator.
- Monitor download results no longer block on SQLite, and UI queries use read-only connections. The monitor database stops storing raw API payloads; a one-time migration slims and vacuums it (a 2 GB library became 210 MB).
- Creator-page gallery player: live photo pictures now play their clip (muted, in step with the gallery music) while still pictures stay static. Galleries with live photos are no longer misdetected as videos (the black 00:11 player / "第 N 张图片加载失败" on the merged `_live_N.jpg`/`.mp4`), clips are placed on their picture from the saved JSON, and pictures missing from older asset rows are found next to the archive. Pictures now advance on their own fixed clock (4 s, or one pass of a live clip) instead of slicing the music's length; the music simply loops, and paging or clicking a segment never seeks it. Galleries without music advance too.
- Settings page trimmed to choices users actually make. Per-work folders, concurrent downloads, retry count, browser fallback and the filename/folder templates are no longer shown; existing saved values keep working. The quality re-download moved to 下载记录 behind a confirmation dialog, and the publish-date range moved to 用户作品 as a per-download filter that is never saved (a range saved by older builds is cleared on startup, so it can no longer silently narrow monitor scans).
- Creator folders under 关注主播 / 用户主页 are named after the creator's current nickname and recognised by a hidden `.author.json` ID marker. When a creator renames themselves, the folder is renamed on their next download (only while none of their files are being written) and every stored path in the archive is rewritten in the same step; folders split by earlier renames are merged. Two creators with the same nickname are told apart as `名字 (uid)`. The 作者文件夹名 setting is no longer shown.
- The footer download lane now shows only `下载 xx/yy`. `monitor_primary_concurrency` / `monitor_sidecar_concurrency` / `monitor_detail_concurrency` are replaced by `monitor_connections` and `monitor_segments`.

- Creator homepage, work cards and the video / 图文 player are now rendered from project-authored markup and styles (`gui/web/creator/`). The captured Douyin page DOM (`official/templates.js`, which also carried a real account's profile and signed CDN links) and the ~2 MB of Douyin production CSS are removed. The homepage follows the app's light / dark theme, and the rest of the app now uses its own font stack and scrollbar rules instead of the ones the captured CSS forced globally.
- The new release baseline excludes captured pages and private workbench history. Old GitHub PR references and cached views require separate cleanup before public release.
- Hardened self-hosted GitHub Actions so public pull requests do not execute automatically on maintainer hardware.
- Updated CI to compile, lint, test, build, and smoke-test the current project layout.
- Cleaned public documentation, examples, and repository hygiene rules.
